# Sprints y Seguimiento

Aunque el proyecto usa prototipado evolutivo, se organizan sprints para planear y controlar cada evolucion del prototipo.

Archivo fuente:

```text
docs/gestion-proyecto/tareas-sprints.csv
```

## Sprint 1: Fundamentos del proyecto

**Fechas:** 2026-05-07 a 2026-05-10  
**Objetivo:** organizar estructura, documentacion y dataset inicial.

Entregables:

- Repositorio estructurado.
- Guia de inicio.
- Dataset inicial.
- Primeras pruebas de camara.

## Sprint 2: Modelo inicial, app y carga

**Fechas:** 2026-05-10 a 2026-05-14  
**Objetivo:** entrenar modelo inicial, integrarlo en Android y documentar pruebas JMeter.

Entregables:

- Modelo TensorFlow Lite.
- App Android con assets.
- Plan JMeter.
- Documento de pruebas de carga.

## Sprint 3: Reconocimiento dinamico

**Fechas:** 2026-05-15 a 2026-05-18  
**Objetivo:** capturar senas dinamicas, entrenar modelo dinamico y mejorar precision.

Entregables:

- Script multicamara.
- Clase `desconocido`.
- Modelo dinamico con 19 clases.
- APK instalado en Android.
- Mejora de interfaz y audio automatico.

Metricas:

- Accuracy dinamico: 86.61%.
- Clase `desconocido` con F1 aproximado 0.83.

## Sprint 4: Cierre y validacion

**Fechas:** 2026-05-19 a 2026-05-25  
**Objetivo:** formalizar gestion, pruebas, evidencias y entrega final.

Pendientes principales:

- Crear tablero en plataforma colaborativa.
- Subir backlog y casos de prueba.
- Adjuntar evidencias visuales.
- Ejecutar pruebas finales en celular.
- Compartir enlace de acceso.

## Definicion de terminado

Una tarea esta terminada cuando:

- Tiene implementacion o documentacion.
- Tiene evidencia.
- Fue probada si afecta funcionalidad.
- El estado del tablero fue actualizado.
- Si fallo, tiene defecto asociado y revalidacion.
